# 🍕 BRD-028 — Publish architecture analysis artifacts from CI

## Status

Planned

## Goal

Make the current Bredland architecture-analysis outputs available from successful GitHub Actions runs.

The project already generates useful architecture-analysis files locally. This slice adds CI generation and publication so the current dependency structure and compiler hierarchy can be inspected easily without reproducing the analysis environment locally.

The first implementation shall remain deliberately small: generate the existing outputs, render the dependency graph to PNG, and upload the results as a GitHub Actions artifact.

---

## Design

### Architecture analysis outputs

The CI workflow shall generate the existing architecture-analysis outputs:

```text
build/analysis/php-dependencies.dot
build/analysis/compiler-hierarchy.txt
```

The dependency graph shall also be rendered to PNG using Graphviz:

```text
build/analysis/php-dependencies.png
```

The analysis itself shall retain its existing behaviour. This slice does not redesign the architecture-report tooling.

---

### GitHub Actions artifact

A successful workflow run shall upload the analysis outputs as a single GitHub Actions artifact.

Suggested artifact name:

```text
architecture-analysis
```

The artifact shall contain:

```text
php-dependencies.dot
php-dependencies.png
compiler-hierarchy.txt
```

The bundle should be easy to download and inspect when:

- refreshing understanding of the current architecture;
- reviewing dependency relationships;
- investigating unexpected architectural drift;
- preparing for refactoring or code review.

---

### Workflow integration

Architecture-analysis generation shall run as part of the normal CI workflow.

The implementation should reuse the existing analysis commands rather than duplicating their behaviour inside the workflow.

The workflow shall remain straightforward to read and maintain.

---

## Acceptance Criteria

- [ ] CI generates `php-dependencies.dot`.
- [ ] CI generates `compiler-hierarchy.txt`.
- [ ] CI renders `php-dependencies.dot` to `php-dependencies.png` using Graphviz.
- [ ] A successful GitHub Actions run uploads a single architecture-analysis artifact.
- [ ] The artifact contains `php-dependencies.dot`.
- [ ] The artifact contains `php-dependencies.png`.
- [ ] The artifact contains `compiler-hierarchy.txt`.
- [ ] The published outputs match the existing local architecture-analysis behaviour.
- [ ] Existing test and CI behaviour remains unchanged apart from the additional analysis generation and artifact upload.
- [ ] The workflow remains simple and understandable.

---

## Out of Scope

- Rendering architecture diagrams directly in the GitHub Actions job summary.
- Publishing analysis outputs outside GitHub Actions.
- Automatically comparing architecture output between commits.
- Failing CI because architecture structure has changed.
- Generating permanent architecture documentation under `docs/`.
- Redesigning the existing architecture-analysis tools.
- Adding new analysis formats.

---

## Notes

This slice is intended as an inspection aid, not an architectural gate.

The generated outputs provide a convenient snapshot of the current code structure from any successful CI run, making it easier to revisit the architecture after time away from the project or to investigate suspected dependency drift.

Inline rendering in the GitHub job summary may be considered later if it proves useful and can be implemented without adding disproportionate publishing complexity.

For this slice, downloadable artifacts are sufficient.
