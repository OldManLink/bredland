# 🍕 BRD-025 — Improve test runner selection and output

## Status

Planned

## Goal

Make the Bredland test runner faster and less noisy to use during development by allowing developers to select which suites run and how much successful output is shown.

The existing `tests/run-all.sh` runner shall remain the canonical entry point.

This slice improves developer ergonomics only. It does not change test semantics, test discovery, or existing deployment behaviour.

---

## Design

### Suite selection

The test runner shall support selecting individual suites or groups of suites.

Selection should build on the runner’s existing glob-based discovery where practical.

Examples may include:

```text
tests/run-all.sh 'php:card*'
tests/run-all.sh 'sh:*deploy*'
```

Multiple selections may be supported where useful.

---

### Language groups

The runner shall provide convenient selection of:

* PHP suites only;
* shell suites only.

These should compose naturally with the existing runner rather than introducing separate test commands.

---

### Listing suites

Add:

```text
--list
```

This shall display the suites currently available to the runner without executing them.

The output should provide enough information for a developer to use the suite-selection syntax easily.

---

### Rerunning failures

Add:

```text
--failed
```

This shall rerun only the suites that failed during the previous test run.

The stored failure information should remain local development state and must not affect test semantics or production behaviour.

If there are no recorded failures, the runner should behave clearly and predictably rather than silently running an unrelated set of tests.

---

### Failures-only output

Add a failures-only output mode.

In this mode:

* successful suites produce no output;
* failed suites remain clearly identified;
* useful failure diagnostics are preserved;
* the final result still clearly indicates whether the overall run passed or failed.

This mode is intended for interactive development where the developer wants to see only actionable failures.

---

### Existing verbosity

Existing `-q` and `-qq` behaviour shall be preserved.

Current callers, including deployment scripts, shall not require modification.

Suite selection and output verbosity shall be orthogonal so they compose naturally.

For example:

```text
tests/run-all.sh -qq 'php:card*'
tests/run-all.sh --failed
```

---

## Acceptance Criteria

* [ ] Individual test suites can be selected.
* [ ] Groups of suites can be selected using glob-style matching.
* [ ] PHP-only test selection is supported.
* [ ] Shell-only test selection is supported.
* [ ] `--list` displays the suites available to the runner.
* [ ] `--failed` reruns only suites that failed during the previous run.
* [ ] A failures-only output mode completely suppresses successful-suite output.
* [ ] Failure diagnostics remain useful in failures-only mode.
* [ ] Existing `-q` behaviour is preserved.
* [ ] Existing `-qq` behaviour is preserved.
* [ ] Existing callers do not need to change.
* [ ] Suite selection and verbosity options compose naturally.
* [ ] Existing test discovery and pass/fail semantics remain unchanged.

---

## Out of Scope

* Changed-file inference.
* Mapping production files to affected tests.
* Automatic dependency analysis.
* Parallel test execution.
* Test prioritisation.
* Changing the existing test framework.
* Changes to production code.

---

## Notes

This slice is deliberately about making the existing test system easier to drive.

As the suite grows, developers should be able to answer simple questions quickly:

```text
What suites exist?
Run only this area.
Run only PHP tests.
Run only shell tests.
Show me only failures.
Rerun what just failed.
```

These capabilities should remain small, composable additions to `tests/run-all.sh`, not the beginning of a more elaborate test-selection system.
