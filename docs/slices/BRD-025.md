# 🍕 BRD-025 — Improve test runner selection and output

## Status

Complete

## Goal

Make the Bredland test runner faster and less noisy to use during development by allowing developers to select which suites run and how much successful output is shown.

The existing `tests/run-all.sh` runner remains the canonical entry point.

This slice improves developer ergonomics only. It does not change test semantics, test discovery, or existing deployment behaviour.

---

## Design

### Suite selection

The test runner supports selecting individual suites or groups of suites using stable suite identifiers and glob-style matching.

Examples:

```text
tests/run-all.sh php:card
tests/run-all.sh 'php:card*'
tests/run-all.sh 'sh:*deploy*'
tests/run-all.sh php:card php:card-head php:notification-badge
```

Suite identifiers use these prefixes:

```text
php:
sh:
```

Nested suites retain their relative path, for example:

```text
php:compiler/type-val
```

Selectors that match no suites are reported as errors rather than being silently ignored. This also applies when some supplied selectors match and others do not.

---

### Language groups

The runner provides convenient aliases for selecting all suites in one language group:

```text
tests/run-all.sh php
tests/run-all.sh shell
```

These are equivalent to:

```text
tests/run-all.sh 'php:*'
tests/run-all.sh 'sh:*'
```

If only one language group is selected, the other language runner is skipped entirely.

---

### Listing suites

Add:

```text
--list
```

This displays the suites selected by the current selector expression without executing them.

Examples:

```text
tests/run-all.sh --list
tests/run-all.sh --list php
tests/run-all.sh --list 'php:card*'
tests/run-all.sh --failed --list
```

With no selector, all available suites are listed.

---

### Rerunning failures

Add:

```text
--failed
```

This reruns only the suites that failed during the previous test run.

Failed suite identifiers are stored as local development state in:

```text
build/test-results/failed-suites
```

The failure file contains the same canonical suite identifiers used by normal selection.

A `--failed` run replaces the previous failure set with the failures from the new run, so the list naturally shrinks as failures are fixed.

If no failed suites remain, the runner reports:

```text
✅ No failed suites from the previous run.
```

and exits successfully without running unrelated tests.

---

### Failures-only output

Add:

```text
--failures-only
```

In this mode:

* successful suites produce no individual suite output;
* failed suites remain clearly identified;
* useful failure diagnostics are preserved;
* suite and overall summaries remain visible so it is clear that the requested tests actually ran;
* the final result still clearly indicates whether the overall run passed or failed.

The option composes with `-q`, allowing successful suites to remain silent while reducing output from failing suites to the failing assertions.

Examples:

```text
tests/run-all.sh --failures-only
tests/run-all.sh --failures-only php
tests/run-all.sh --failures-only php -q
```

---

### Existing verbosity

Existing `-q` and `-qq` behaviour is preserved.

Current callers, including deployment scripts, do not require modification.

Suite selection and output verbosity remain orthogonal and compose naturally.

Examples:

```text
tests/run-all.sh -q 'php:card*'
tests/run-all.sh -qq 'php:card*'
tests/run-all.sh --failures-only -q
tests/run-all.sh --failed
```

`-qq` remains suitable for deployment use: successful runs emit only the final result, while failed runs replay the captured diagnostics.

---

### Runner output

Successful Docker build output is captured and suppressed. If the Docker build fails, its captured diagnostics are printed.

The raw start/end timestamps have been replaced by a final elapsed-time result, for example:

```text
✅ All tests passed, elapsed time: 11s
```

or:

```text
❌ Test failures, elapsed time: 15s
```

## Acceptance Criteria

* ✅ Individual test suites can be selected.
* ✅ Groups of suites can be selected using glob-style matching.
* ✅ PHP-only test selection is supported.
* ✅ Shell-only test selection is supported.
* ✅ `--list` displays the suites available to the runner.
* ✅ `--failed` reruns only suites that failed during the previous run.
* ✅ A failures-only output mode completely suppresses successful-suite output.
* ✅ Failure diagnostics remain useful in failures-only mode.
* ✅ Existing `-q` behaviour is preserved.
* ✅ Existing `-qq` behaviour is preserved.
* ✅ Existing callers do not need to change.
* ✅ Suite selection and verbosity options compose naturally.
* ✅ Existing test discovery and pass/fail semantics remain unchanged.

---

## Out of Scope

* Changed-file inference.
* Mapping production files to affected tests.
* Automatic dependency analysis.
* Parallel test execution.
* Test prioritisation.
* Changing the existing test framework.
* Changes to production code.

---

## Notes

This slice is deliberately about making the existing test system easier to drive.

As the suite grows, developers can now answer simple questions quickly:

```text
What suites exist?
Run only this area.
Run only PHP tests.
Run only shell tests.
Show me only failures.
Rerun what just failed.
```

The implementation keeps these capabilities as small, composable additions to `tests/run-all.sh` rather than introducing a more elaborate test-selection system.

The remaining work before the slice is complete is to add regression coverage for the new runner behaviour and perform the final compatibility pass.
