# 🍕 BRD-023 — Cache the PHP 5.5 Docker image in CI

## Status

Complete

## Goal

Reduce GitHub Actions runtime and minute consumption by caching the layers of the PHP 5.5 Docker test image between workflow runs.

The current workflow spends approximately 80 of its 98 seconds rebuilding the image on every run, even when its Dockerfile and build inputs have not changed.

This slice introduces Docker Buildx layer caching while preserving the existing test behaviour and keeping the workflow simple to understand.

---

## Design

### Buildx layer cache

Configure the GitHub Actions workflow to build the PHP 5.5 test image using Docker Buildx.

The build shall use a cache that persists between workflow runs so unchanged image layers can be reused.

A workflow run without a usable cache shall build the image normally and populate the cache for subsequent runs.

---

### Single image build

The PHP 5.5 image shall be built no more than once during a workflow run.

All PHP 5.5 tests and syntax checks shall use that same locally available image.

The caching implementation must not introduce a separate cache-population build followed by another build for test execution.

---

### Existing validation behaviour

The slice shall preserve the current validation workflow, including:

- all existing PHP 5.5 tests;
- all existing `php -l` checks;
- the current pass/fail behaviour;
- the existing PHP compatibility guarantees.

Only the construction and reuse of the Docker test image shall change.

---

### Verification

The implementation shall be verified using at least two consecutive workflow runs:

1. A run without an existing usable cache, which builds the image and populates the cache.
2. A subsequent run with unchanged build inputs, which reuses the cached layers.

The workflow output shall make cache use observable enough to verify that the second run did not perform the full PHP 5.5 build again.

---

## Acceptance Criteria

-  ✅ The PHP 5.5 Docker image is built using Docker Buildx.
-  ✅ Docker image layers are cached between GitHub Actions workflow runs.
-  ✅ A first run without a usable cache successfully builds the image and populates the cache.
-  ✅ A second run with unchanged build inputs reuses cached layers.
-  ✅ The PHP 5.5 image is not built twice within a single workflow run.
-  ✅ All existing PHP tests continue to run unchanged.
-  ✅ All existing `php -l` checks continue to run unchanged.
-  ✅ Existing workflow failure behaviour is preserved.
-  ✅ The workflow remains simple and understandable.
-  ✅ CI runtime before and after caching is measured and documented.

The cached workflow completed in 32 seconds, compared with the approximately
98-second baseline measured before this slice.

---

## Out of Scope

- Changing the PHP 5.5 Docker image itself.
- Changing the test suite or syntax checks.
- Caching unrelated workflow dependencies.
- Redesigning the wider GitHub Actions workflow.
- Optimising production deployment.
- Changes to BRD-022.

---

## Notes

This slice is intentionally independent of BRD-022 and may be merged immediately.

Its purpose is to remove repeated infrastructure work from every CI run so that subsequent development receives faster feedback and consumes fewer GitHub Actions minutes.

Cache invalidation should follow the image’s genuine build inputs. When the Dockerfile or another relevant input changes, the affected layers must be rebuilt rather than allowing a stale image to conceal the change.
